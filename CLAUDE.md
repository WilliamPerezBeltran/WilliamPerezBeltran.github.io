# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

William Fernando Pérez's personal site (résumé / projects / inspiration), built with
Create React App (`react-scripts` 4) and `react-router-dom` v6. The design is a
deliberate visual clone of http://theengineer.co — do not "modernize" the look
without being asked; changes should stay pixel-consistent with that reference.

## Commands

```bash
npm start            # dev server on :3000
npm run build         # production build to build/
npm test              # Jest + React Testing Library (react-scripts test)
npm run deploy         # build + publish build/ to the gh-pages branch (GitHub Pages)
```

Single test file today is `src/App.test.js`; `npm test -- --watchAll=false` runs once
non-interactively (useful for CI-style checks).

### Node version — important

`react-scripts` 4 uses Webpack 4, which breaks on Node 17+ with
`ERR_OSSL_EVP_UNSUPPORTED` (OpenSSL 3 removed the legacy digest Webpack 4 relies on).
**Use Node 16.x** (this repo was developed against 16.20.2). If you must use a newer
Node, prefix build/start commands with `NODE_OPTIONS=--openssl-legacy-provider`.

## Architecture

**Routing**: `src/App.js` wraps everything in `HashRouter` (not `BrowserRouter`) so the
site works on GitHub Pages (a static host) without server-side rewrite rules. Four
routes, one component each in `src/pages/`: `Home.js` (`/`), `CV.js` (`/cv`),
`Projects.js` (`/projects`), `Inspiration.js` (`/inspiration`). All non-Home pages
share `src/components/Footer.js`, which takes a `current` prop (`"home" | "cv" |
"projects" | "inspiration"`) and renders that page's own nav entry as plain text
instead of a link — this matches how the reference site's footer nav behaves.

**Styling is NOT CSS-in-JS.** `src/App.css` and `src/index.css` are intentionally
near-empty (CRA boilerplate stripped out). All real styling lives in global
stylesheets loaded via `<link>` tags in `public/index.html`, loaded in this cascade
order, mirroring theengineer.co's own stylesheet setup exactly:

1. `public/assets/css/normalize.css` — untouched vendor reset
2. `public/assets/css/skeleton.css` — untouched vendor grid framework (`.container`,
   `.row`, `.columns`, `.two`/`.four`/`.ten`/`.twelve` column widths, base
   typographic defaults). Don't "clean up" rules in here that look redundant with
   `style.css` — the redundancy is how the source site's cascade actually works
   (skeleton.css sets defaults, style.css overrides specific properties on top).
3. `public/assets/css/style.css` — the actual site theme: fonts, colors, the `.cv`
   scoped overrides used by CV/Projects/Inspiration pages, footer/link spacing.

Fonts: **Inconsolata** (body text), **Source Code Pro** (h3, nav-style links) via
Google Fonts in `index.html`; **Grotesk** (h1/h2/h4) is a self-hosted webfont in
`public/assets/fonts/` (`@font-face` in `style.css`) — no CDN source exists for it.

Page layout pattern used throughout `pages/`: `.container` (`.cv` added on résumé-style
pages) → `.row` → column divs. A two-column date + ten-column content pattern
(`<div className="two columns"><h3>{date}</h3></div>` next to
`<div className="ten columns">...</div>`) is used for every Experience/Education
entry in `CV.js`. Skills/Projects/Inspiration list rows use plain `.ten.columns`
(no leading offset column — that offset is only used in the paired date/content
rows, not standalone list rows; don't add a spacer `<div className="two columns
hidden-small">` to those or the content misaligns vs. the reference).

**Icons**: `public/favicon.ico`, `logo192.png`, `logo512.png`, `apple-touch-icon.png`
are plain PNGs (browsers accept PNG-formatted `.ico`). No ImageMagick/rsvg-convert is
available in this environment — icons were generated by rendering an HTML page with
Playwright/Chromium at the exact target pixel size and screenshotting it (see prior
session for the throwaway script pattern: viewport = icon size, `deviceScaleFactor:
1`, screenshot the page). Regenerate the same way if the icon needs to change.

**Deploy**: GitHub Pages via the `gh-pages` npm package (`predeploy`/`deploy`
scripts). `homepage` in `package.json` must match the actual Pages URL — a plain
`https://<user>.github.io` root (no subpath) only works if the repo is literally
named `<user>.github.io`; otherwise it must include `/<repo-name>`.

**Dead weight**: `public/assets/img/` and most of `public/assets/vendor/` are leftovers
from the original Bootstrap template this project started from. Nothing in `src/`
references them anymore — safe to ignore, and safe to delete if asked.

**Content accuracy**: CV/Projects content is William's real résumé data, not
placeholder copy — when editing `src/pages/CV.js` or `Projects.js`, don't invent
employers, metrics, or dates. `Inspiration.js` entries are real people but not
necessarily final — treat additions there as more casual/example-friendly than the
résumé itself.
